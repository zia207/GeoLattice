Why fuzzy?¶

Part I used crisp criteria. A county either had a need index of at least 100 or it did not. Chautauqua County, with an ICU-bed LQ of 1.00, failed the capacity criterion even though it was practically identical to counties that passed.

Real-world criteria rarely have sharp edges:

  • Is a 4% slope "gentle"? Mostly. Is 6%? Partly. Is 15%? Not really.
  • Is a site 105 km from a hospital "close"? Somewhat.

Fuzzy set theory (Zadeh, 1965) replaces the yes/no of crisp sets with a degree of membership μ between 0 and 1:

Set type Membership of x in set A
Crisp μ_A(x) ∈ {0, 1}
Fuzzy μ_A(x) ∈ [0, 1]

A membership of 0.8 means "largely belongs to the set of suitable values". It is a degree of truth, not a probability. Nothing is random: the slope is known exactly, and the uncertainty lies in what gentle means.

Under the crisp rule, 4.9% and 5.1% get completely different scores. Under the fuzzy rule, they are practically equal (about 0.52 and 0.48), which matches how a planner would actually think about them.

The fuzzy suitability workflow¶

  1. Fuzzification: transform each criterion to a membership in the set suitable with a membership function.
  2. Optional hedging: make a membership stricter or more lenient.
  3. Fuzzy overlay: combine memberships with a fuzzy operator.
  4. Interpretation: map, threshold, and rank the combined membership.

The next sections build each piece.

Membership functions¶

The functions below follow the definitions in the ArcGIS Fuzzy Membership tool, so results can be checked against ArcGIS. In each formula, $f_1$ and $f_2$ are the function's two shape parameters.

Function Formula Shape Use when
Gaussian $\mu = e^{-f_2 (x - f_1)^2}$ Bell curve, peak at midpoint $f_1$ An ideal value exists (optimal temperature)
Near $\mu = \dfrac{1}{1 + f_1 (x - f_2)^2}$ Narrow peak, heavier tails Values near a target
Small $\mu = \dfrac{1}{1 + (x/f_2)^{f_1}}$ Decreasing S-curve Small values are favorable (slope, distance)
Large $\mu = \dfrac{1}{1 + (x/f_2)^{-f_1}}$ Increasing S-curve Large values are favorable (yield, need)
Linear $\mu = \dfrac{x - \min}{\max - \min}$, clipped to 0-1 Straight ramp Simple monotonic relationship
MS Small $\mu = \dfrac{b s}{x - a m + b s}$ for $x > a m$, else 1 Data-driven decrease Skewed data, small values favorable
MS Large $\mu = 1 - \dfrac{b s}{x - a m + b s}$ for $x > a m$, else 0 Data-driven increase Skewed data, large values favorable

For Small and Large, $f_2$ is the midpoint (where μ = 0.5) and $f_1$ is the spread, which controls steepness. For Gaussian and Near, the midpoint is the peak. In MS Small and MS Large, m and s are the mean and standard deviation of the data, and a and b are user multipliers.

Small and Large require positive values. Gaussian, Near, and Linear accept any real values.

How the spread parameter works¶

For Small and Large, the spread controls how quickly membership moves from 1 to 0 around the midpoint. Low spread produces a gentle transition and high spread approaches a crisp threshold. For Gaussian and Near, a larger spread produces a narrower peak, which can seem counterintuitive.

Choosing the parameters¶

The parameters translate expert knowledge into a curve. A practical recipe:

  1. Pick the value where the criterion is "neither suitable nor unsuitable". That value is the midpoint (μ = 0.5).
  2. Pick a value that is "clearly suitable" (say μ = 0.9) and solve for the spread.

For the Small function, $\mu(x_{0.9}) = 0.9$ gives $f_1 = \ln(1/9) / \ln(x_{0.9}/f_2)$:

In [7]:
# Solve for a Small-function spread so mu(3) ~= 0.9 when midpoint = 5 (gentle slope example).
sp = spread_for_small(midpoint=5, x_at_09=3)  # slope: 5% neutral, 3% clearly gentle
print(f"spread = {sp:.2f}")  # calibrated spread
print("check mu(3) =", round(float(fz.small(3, 5, sp)), 3), "| mu(5) =", float(fz.small(5, 5, sp)))  # verify

spread = 4.30
check mu(3) = 0.9 | mu(5) = 0.5

Data-driven membership: MS Small and MS Large¶

MS Small and MS Large set the transition point from the data's mean and standard deviation, which helps when there is no expert threshold. They are applied here to a right-skewed (log-normal) sample.

Cross-checking with scikit-fuzzy¶

scikit-fuzzy uses a different parameterization. Its gaussmf takes a standard deviation σ, which corresponds to an ArcGIS spread of $1/(2\sigma^2)$. A quick numerical check confirms that the implementations agree:

In [9]:
# Cross-check GeoLattice gaussian against scikit-fuzzy gaussmf under matched parameters.
import skfuzzy as skf  # scikit-fuzzy membership helpers

sigma = 10  # scikit-fuzzy Gaussian width
ours = fz.gaussian(x, 50, 1 / (2 * sigma ** 2))  # GeoLattice spread = 1/(2 sigma^2)
theirs = skf.gaussmf(x, 50, sigma)  # scikit-fuzzy Gaussian MF
print("max |difference| =", np.abs(ours - theirs).max())  # should be near machine epsilon

Hedges¶

Hedges modify a fuzzy set the way adverbs modify a word:

  • Very (concentration), $\mu^2$, makes the set stricter: a value with μ = 0.7 drops to 0.49.
  • Somewhat (dilation), $\mu^{0.5}$, makes it more lenient: 0.7 rises to 0.84.

Use them when stakeholders say a criterion should be applied "strictly" or "loosely" without changing its midpoint.

In [10]:
# Demonstrate hedges: very (concentration) and somewhat (dilation) on a Small membership.
mu = fz.small(x, 40, 4)  # base membership "gentle"
plt.plot(x, mu, lw=2.5, label="gentle")  # original set
plt.plot(x, fz.very(mu), lw=2, ls="--", label="very gentle (mu^2)")  # concentration
plt.plot(x, fz.somewhat(mu), lw=2, ls="-.", label="somewhat gentle (sqrt(mu))")  # dilation
plt.xlabel("x"); plt.ylabel("mu"); plt.title("Hedges")  # axis labels / title
plt.legend(); plt.grid(alpha=0.3)  # legend and light grid
plt.show()  # render the figure

Fuzzy overlay operators¶

After fuzzification, the criteria are combined. For memberships $\mu_1 \dots \mu_n$ at a location:

Operator Formula Behavior Analogy
AND $\min(\mu_i)$ Result equals the weakest criterion "All criteria must be met", the fuzzy version of Boolean AND
OR $\max(\mu_i)$ Result equals the strongest criterion "Any criterion is enough"
Product $\prod \mu_i$ Less than or equal to the smallest input; decreasive Each weakness compounds
Sum $1 - \prod (1 - \mu_i)$ Greater than or equal to the largest input; increasive Each strength adds up
Gamma $(\text{Sum})^{\gamma} \cdot (\text{Product})^{1 - \gamma}$ Between Product (γ = 0) and Sum (γ = 1) Tunable compromise

The fuzzy Sum is not an algebraic sum. Combining two memberships of 0.5 gives 0.75, not 1.0.

The order of the results always holds for any location: Product ≤ AND ≤ inputs ≤ OR ≤ Sum. Gamma can fall anywhere between Product and Sum.

In [11]:
# Compare fuzzy overlay operators on four illustrative membership triplets.
mu_a = np.array([0.9, 0.9, 0.5, 0.2])  # criterion A across four cases
mu_b = np.array([0.8, 0.3, 0.5, 0.2])  # criterion B across four cases
mu_c = np.array([0.7, 0.9, 0.5, 0.9])  # criterion C across four cases

import pandas as pd  # (also imported at setup; kept here for self-contained cell)
table = pd.DataFrame({"mu_A": mu_a, "mu_B": mu_b, "mu_C": mu_c},
                     index=["All good", "One weak", "All average", "Mostly poor"])  # case labels
# Evaluate standard overlay operators column-wise.
for m in ["and", "or", "product", "sum"]:
    table[m.upper()] = fz.overlay([mu_a, mu_b, mu_c], m)  # AND/OR/PRODUCT/SUM
# Evaluate GAMMA at two gamma settings.
for g in [0.5, 0.9]:
    table[f"GAMMA {g}"] = fz.overlay([mu_a, mu_b, mu_c], "gamma", gamma=g)  # gamma blend
table.round(3)  # display rounded comparison table

Reading the table:

  • One weak (0.9, 0.3, 0.9): AND gives 0.3 because the weak criterion dominates. Product gives 0.24, which is even lower. Sum gives 0.99, so the weakness is almost ignored.
  • All average (0.5, 0.5, 0.5): Product falls to 0.125 while Sum rises to 0.875. The two operators diverge as more criteria are added.
  • Gamma 0.9 sits in between, but much closer to Sum, because γ near 1 weights the increasive component.

Response surfaces for two criteria¶

Plotting each operator over every pair of input values shows its logic at a glance.

In [12]:
# Response surfaces: how each overlay operator combines two membership inputs.
g = np.linspace(0, 1, 101)  # membership grid on [0, 1]
A, B = np.meshgrid(g, g)  # all pairs (mu1, mu2)
ops = [("AND (min)", "and", None), ("OR (max)", "or", None), ("Product", "product", None),
       ("Sum", "sum", None), ("Gamma 0.5", "gamma", 0.5), ("Gamma 0.9", "gamma", 0.9)]  # panels

fig, axes = plt.subplots(2, 3, figsize=(12, 7.5))  # 2x3 grid of surfaces
for ax, (title, m, gm) in zip(axes.ravel(), ops):
    Z = fz.overlay([A, B], m, gamma=gm if gm is not None else 0.9)  # combined membership surface
    cs = ax.contourf(A, B, Z, levels=np.linspace(0, 1, 11), cmap="RdYlGn")  # filled contours
    ax.contour(A, B, Z, levels=[0.5], colors="k", linewidths=1)  # mu = 0.5 isoline
    ax.set_title(title)  # operator name
    ax.set_xlabel("mu1"); ax.set_ylabel("mu2")  # input membership axes
    ax.set_aspect("equal")  # square panels
fig.colorbar(cs, ax=axes, shrink=0.8, label="Combined membership")  # shared colourbar
plt.suptitle("Fuzzy overlay response surfaces (black line: mu = 0.5)")  # figure title
plt.show()  # render the figure

How γ moves the result¶

As γ moves from 0 to 1, the result moves from Product to Sum. Values of γ between about 0.7 and 0.9 are common in practice because they balance the two. For the three-criterion "one weak" example:

In [13]:
# Trace how gamma moves the combined membership for a fixed input triplet.
gammas = np.linspace(0, 1, 51)  # gamma from pure product-like to sum-like
case = [np.array([0.9]), np.array([0.3]), np.array([0.9])]  # one weak criterion among two strong
vals = [float(fz.overlay(case, "gamma", gamma=gm)[0]) for gm in gammas]  # gamma curve

plt.plot(gammas, vals, lw=2.5)  # combined mu vs gamma
plt.axhline(float(fz.overlay(case, "and")[0]), ls="--", color="grey", label="AND (min)")  # AND reference
plt.xlabel("gamma"); plt.ylabel("Combined mu")  # axis labels
plt.title("Gamma overlay for inputs (0.9, 0.3, 0.9)")  # panel title
plt.legend(); plt.grid(alpha=0.3)  # legend and light grid
plt.show()  # render the figure

Choosing an operator¶

Decision logic Operator
All criteria are essential, and the weakest one limits suitability AND
Any single criterion qualifies a site OR
Weaknesses compound, so the result should be conservative Product
Strengths reinforce each other Sum
A balance between the two, tuned with γ Gamma

Note that fuzzy overlay has no criterion weights. The operator controls how criteria interact, and importance can be expressed through membership parameters or hedges. Module 8 discusses weighting fuzzy criteria explicitly.

Key takeaways¶

  • A fuzzy membership is a degree of suitability between 0 and 1, not a probability.
  • Membership functions encode expert knowledge. The midpoint is the μ = 0.5 point and the spread controls steepness.
  • Hedges make sets stricter or more lenient.
  • Overlay operators range from strict (Product, AND) to lenient (OR, Sum), and Gamma moves smoothly between Product and Sum.
  • geolattice.spatial_analysis.multi_criteria_suitability_analysis now holds all of these functions for the following modules.
