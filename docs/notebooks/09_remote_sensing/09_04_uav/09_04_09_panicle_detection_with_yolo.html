Panicle Detection with YOLO

Panicles per square metre is a direct component of rice yield.

Overview

From late September the LUMS frames show pale, cream-coloured panicles above the leaves, and the study counted them with a fine-tuned YOLOv5 detector run in sliding windows (1024 px, stride 512) over the orthomosaic, keeping boxes above 0.7 confidence and merging overlaps with non-maximum suppression (NMS) at IoU 0.4. This notebook builds that pipeline with rs.uav.tiled_detect and friends. A detector is any function tile -> boxes, so the windowing, merging, counting and scoring are first checked on a synthetic scene with known answers and then run on real frames with a simple colour-based candidate detector; the LUMS YOLOv5 weights plug into the same call when downloaded.

Core concepts

Learning objectives

  1. Lay out sliding windows and understand why objects cut by window edges inflate counts.
  2. Merge window detections back into image coordinates with cross-window NMS.
  3. Score detections against reference boxes: precision, recall, F1 and count agreement.
  4. Convert boxes to polygons and compute panicles per m².
  5. Run a YOLO model (ultralytics or YOLOv5) in the same pipeline and prepare a small labelled set for fine-tuning.

Data

Data Type
LUMS rice frames, 17 Sep to 3 Oct 2025, panicle stage, 1.85 mm/px Real (CC BY 4.0)
Synthetic scene with known boxes, used to check windowing and NMS Simulated
The paper’s reference panicle counts Not in the public release

Sliding windows

A 3840 × 2160 frame is larger than a detector’s input. detection_windows(H, W, window, stride) lays out windows with stride steps; with stride = window / 2 every object away from the image border falls wholly inside at least one window. The last row and column of windows are shifted back to end exactly at the image edge.

Checking the machinery on a scene with known answers

Before trusting a count, check the windowing on a scene where the right answer is known. The synthetic image below has 64 bright squares of 40 px on a dark background; the “detector” finds bright connected components in a window and returns their boxes with confidence 0.95. Squares cut by a window edge come back as partial boxes.

Code 
def square_detector(tile, conf):
    """Toy detector: boxes around bright connected components, confidence 0.95."""
    lab, _ = ndi.label(tile[..., 0] > 128)
    out = [[s[1].start, s[0].start, s[1].stop, s[0].stop, 0.95, 0] for s in ndi.find_objects(lab)]
    return np.array(out, np.float32).reshape(-1, 6)

scene = np.zeros((700, 900, 3), np.uint8)
truth = []
for r in range(30, 680, 90):
    for c in range(30, 880, 110):
        scene[r:r + 40, c:c + 40] = 255
        truth.append((c, r, c + 40, r + 40))
truth = pd.DataFrame(truth, columns=["x1", "y1", "x2", "y2"])
scene_img = rs.uav.as_image(scene)

rows = []
for label, kw in [("no NMS, keep edge boxes", dict(iou=1.01, edge_margin=0)),
                  ("NMS only", dict(iou=0.4, edge_margin=0)),
                  ("NMS + drop edge boxes", dict(iou=0.4, edge_margin=2))]:
    det = rs.uav.tiled_detect(scene_img, square_detector, window=256, stride=128, conf=0.5, **kw)
    rows.append({"setting": label, "detections": len(det), **rs.uav.detection_scores(det, truth, iou=0.5)})

Without NMS every square is counted once per window that sees it. NMS merges full duplicates, but a square cut by a window edge yields a partial box whose IoU with the full box is low, so it survives NMS and inflates the count. Dropping boxes that touch an interior window edge (edge_margin) removes them: the whole object is always found by a neighbouring window when objects are smaller than the overlap (window - stride). For objects larger than the overlap, set edge_margin=0.

Panicle candidates on real frames

Without the trained weights, a simple colour rule stands in for the detector: panicles here are pale cream clusters (bright, low saturation, yellowish hue) above green leaves. The function below finds such pixels, joins them into blobs and returns a box per blob larger than a few square centimetres, with a “confidence” equal to the fraction of candidate pixels in the box (elongated, diagonal blobs fill little of their box, hence the low threshold of 0.15). It also fires on bright leaf midribs and dry leaf tips, so treat its output as candidates; the point is to exercise the pipeline, not to replace a trained model.

Code 
def panicle_candidates(tile, conf, min_area_px=400, max_area_px=20_000):
    """Colour-blob stand-in detector: (n, 6) boxes [x1, y1, x2, y2, score, class]."""
    hsv = cv2.cvtColor(tile, cv2.COLOR_RGB2HSV_FULL).astype(np.float32)
    hue, sat, val = hsv[..., 0] * 360 / 255, hsv[..., 1], hsv[..., 2]
    cand = ((val > 180) & (sat > 30) & (sat < 90) & (hue > 35) & (hue < 80)).astype(np.uint8)
    cand = cv2.morphologyEx(cand, cv2.MORPH_OPEN, np.ones((3, 3), np.uint8))  # drop speckle
    n, lab, stats, _ = cv2.connectedComponentsWithStats(cand, connectivity=8)
    out = []
    for i in range(1, n):
        x, y, w, h, a = stats[i]
        if min_area_px <= a <= max_area_px:
            score = a / float(w * h)  # how much of the box the blob fills
            if score >= conf:
                out.append([x, y, x + w, y + h, score, 0])
    return np.array(out, np.float32).reshape(-1, 6)

YOLO in the same pipeline

rs.uav.load_detector(weights, backend=...) wraps an ultralytics (YOLOv8/11) or YOLOv5 model as a tile -> boxes function, and tiled_detect accepts the weights path directly. The LUMS model is a fine-tuned YOLOv5 (backend="yolov5", loaded through torch.hub).

if RUN_DL:
    weights = rs.uav.fetch_weights("yolov5_rice_panicle")
    yolo = rs.uav.load_detector(weights, backend="yolov5")
    det = rs.uav.tiled_detect(img, yolo, window=1024, stride=512, conf=0.7, iou=0.4, progress=True)

Preparing a small labelled set for fine-tuning

Detectors transfer poorly between varieties, growth stages and camera heights, so a few hundred labelled panicles from your own fields usually pay off. The LUMS model was fine-tuned from COCO weights. The workflow:

  1. Cut frames into 1024 px tiles (the inference size) and keep tiles with panicles.
  2. Label boxes in a tool such as CVAT or Label Studio, exported in YOLO format: one text file per tile, one line per box: class x_centre y_centre width height, all relative to the tile size.
  3. Write a dataset YAML and train with ultralytics.

Summary and exercises

Key points

  • A sliding window cuts panicles on the tile edge, so those boxes have to be dropped or they inflate the count. Overlapping windows are merged with NMS.
  • Score the boxes against a reference: precision, recall, F1 and count agreement.
  • Boxes become polygons, then panicles per square metre.
  • A colour candidate detector and a YOLO model both go through tiled_detect. The windows, the merge and the count stay put when the detector changes.

GeoLattice functions used: rs.uav.tiled_detect, rs.uav.detection_scores, rs.uav.boxes_to_gdf, rs.uav.count_summary, rs.uav.load_detector.
