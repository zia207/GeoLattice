Reading and Writing Vector Data

In this notebook, you will learn how to open, inspect, and export a variety of common vector data formats, such as Shapefile, GeoJSON, and KML, using GeoLattice and some popular Python libraries. We will guide you through basic concepts, explore different file types, demonstrate practical workflows, and show you how to seamlessly convert between formats. Whether you’re new to working with GIS data or looking to expand your practical skills with GeoLattice, this notebook provides hands-on examples to help you understand and manage vector data in your own projects.

Overview

Vector data is a type of geospatial data representation used in Geographic Information Systems (GIS) and computer graphics. It represents spatial information using points, lines, and polygons, which are defined by their geometric coordinates. These coordinates consist of x and y (and sometimes z) values that describe the location of each point, the vertices of lines, or the corners of polygons.

Here’s a breakdown of the main elements of vector data:

  1. Points: A single data point that represents a specific location in space, defined by its x and y coordinates (and potentially z for 3D data). Points are often used to represent features like cities, landmarks, or sampling locations.

  2. Lines (Polylines): A series of connected points, which can be straight or curved, used to represent linear features such as roads, rivers, or boundaries. Lines are composed of multiple vertices that define their shape.

  3. Polygons: Closed shapes formed by connecting a series of lines to enclose an area. Polygons are used to represent features like countries, lakes, forests, and other spatially bounded regions.

Vector data provides a more detailed and accurate representation of geographic features compared to raster data, which is another common data format used in GIS. One of the significant advantages of vector data is that it allows for precise measurements, editing, and analysis of geographic features. It is also more scalable and efficient for storing data with well-defined boundaries and discrete features.

Some common vector data formats include Shapefile (.shp), GeoJSON (.geojson), and Keyhole Markup Language (.kml). These formats can store various attributes along with the spatial coordinates, making it possible to attach additional information (e.g., population data for cities or elevation data for terrain) to each feature represented in the vector dataset.

This tutorial covers the full vector I/O loop: open common desktop and cloud-native formats, inspect layers and geometries, then write features back out with the same GDAL/OGR stack.

Reading. open_vectors_data opens the file formats used by desktop GIS and GPS tools and returns a VectorDataset. open_cloud_native_vector_data opens cloud-native files, lakehouse tables, and GeoParquet profiles and returns a CloudNativeDataset. In both cases the active layer exposes the CRS, extent, fields, and feature count. to_dataframe() returns a GeoPandas GeoDataFrame when GeoPandas is installed. Close either dataset with a with block so the file handle is released.

Writing. write_vector_data uses the same drivers. The file extension selects the driver. write_shapefile, write_geopackage, write_geojson, and write_csv call that function with the driver fixed.

The notebook is organized in three parts:

  1. Reading desktop formats: walk through the GDAL samples in data/data_gdal.
  2. Reading cloud-native layouts: open small local examples of GeoParquet, FlatGeobuf range reads, PMTiles, and related layouts.
  3. Writing vector data: write New York counties to every creatable desktop format, convert the sample files to shapefiles, and read the outputs back for a map check.

The desktop-format files live in data/data_gdal. They are the GDAL sample files shipped with this repository. The cloud-native section writes small local examples, because those layouts are usually published as large objects on object storage. Written files land in Data/00_shared/vector_data/output_folder. Setup

The next cell puts the repository root on the import path, points DATA at the sample directory, prepares the write output folders, and defines the helpers used later:

  • list_layers prints one row per layer.
  • read_vector opens a desktop format with open_vectors_data, prints layer properties, shows a short attribute table, and draws the geometries with plot_layers() from geolattice.viz.
  • read_cloud does the same for a cloud-native layout, and also prints the schema profile, reader, and spatial index.

County outputs go in Data/00_shared/vector_data/output_folder/ny_county. Shapefiles converted from the GDAL samples go in gdal_as_shapefile.

Installation. This notebook needs installation option 1 (vector, raster, CRS and visualization): pip install "geolattice[core]". See “Installation options” in the GeoLattice README.

def preview_table(frame, limit=5):
    # Show the first few rows of a table, with a column for geometry type (like 'Polygon')
    view = frame.head(limit).copy()
    # Call insert()
    view.insert(
        # Statement
        1,
        # Include geom_type
        "geom_type",
        # Call map()
        view["geometry"].map(lambda geom: getattr(geom, "geom_type", None)),
    # Close multi-line expression
    )
    # Set keep
    keep = ["fid", "geom_type"]
    # Set extras
    extras = [name for name in view.columns if name not in keep and name != "geometry"]
    # Return result
    return view[keep + extras[:6]]

# Define plot_frame()
def plot_frame(frame, title):
    # Include 
    """
    # Statement
    Draw a map: shows the shapes in the data as polygons, lines, or points.
    # Statement
    Uses pretty colors and groups things by type.
    # Include 
    """
    # Define plottable()
    def plottable(geom):
        # Only plot real geometry types (not empty/missing stuff)
        return isinstance(geom, BaseGeometry) and not geom.is_empty and geom.geom_type in _PLOT_TYPES

    # Set mask
    mask = frame["geometry"].map(plottable)
    # Set plot_df
    plot_df = frame.loc[mask].copy()
    # If plot_df.empty
    if plot_df.empty:
        # Call print()
        print(f"No point, line, or polygon geometries to draw for {title}.")
        # Return result
        return 0

    # Set kinds
    kinds = plot_df["geometry"].map(lambda geom: geom.geom_type)
    # Set groups
    groups = [
        # Call function()
        (
            # Include polygon
            "polygon",
            # Statement
            ["Polygon", "MultiPolygon"],
            # Statement
            {"facecolor": FACE, "edgecolor": EDGE, "linewidth": 0.6, "alpha": 0.88, "zorder": 1},
        # Close multi-line expression
        ),
        # Call function()
        (
            # Include line
            "line",
            # Statement
            ["LineString", "MultiLineString", "LinearRing"],
            {"color": "#E36414", "linewidth": 1.6, "zorder": 2},
        ),
        # Call function()
        (
            # Include point
            "point",
            # Statement
            ["Point", "MultiPoint"],
            {"color": "#F4A261", "markersize": 42, "edgecolor": "#7A3E00", "linewidth": 0.4, "zorder": 3},
        ),
    # Close multi-line expression
    ]
    # Set layers
    layers = []
    # Loop: label, types, style in groups
    for label, types, style in groups:
        # Set part
        part = plot_df.loc[kinds.isin(types)]
        # If len(part)
        if len(part):
            # Call append()
            layers.append({"data": part, "label": label, **style})
    # Set ax
    ax = plot_layers(layers, title=title, figsize=(7.6, 5.4), legend=len(layers) > 1, show=False)

    # Make sure map has a little space around the data
    minx, miny, maxx, maxy = geometry_bounds(plot_df)
    # Set span_x
    span_x = maxx - minx
    # Set span_y
    span_y = maxy - miny
    # Set pad_x
    pad_x = span_x * 0.08 if span_x else max(abs(minx) * 0.02, 1.0)
    # Set pad_y
    pad_y = span_y * 0.08 if span_y else max(abs(miny) * 0.02, 1.0)
    # Call set_xlim()
    ax.set_xlim(minx - pad_x, maxx + pad_x)
    # Call set_ylim()
    ax.set_ylim(miny - pad_y, maxy + pad_y)
    # Call tight_layout()
    ax.figure.tight_layout()
    # Call show()
    plt.show()
    # Return result
    return len(plot_df)

# Define geometry_bounds()
def geometry_bounds(frame):
    # Find the smallest box that includes all the shapes in the table.
    boxes = []
    # Loop: geom in frame["geometry"]
    for geom in frame["geometry"]:
        # If isinstance(geom, BaseGeometry) and not geom.is_empty
        if isinstance(geom, BaseGeometry) and not geom.is_empty:
            # Call append()
            boxes.append(geom.bounds)
    # If not boxes
    if not boxes:
        # Return result
        return None
    # Return result
    return (
        # Call min()
        min(box[0] for box in boxes),
        # Call min()
        min(box[1] for box in boxes),
        # Call max()
        max(box[2] for box in boxes),
        # Call max()
        max(box[3] for box in boxes),
    # Close multi-line expression
    )

GeoParquet

GeoParquet stores features in a Parquet file and records the geometry column, encoding, bounding box, and CRS in a geo metadata key. A query can read a few columns instead of every attribute. fiboa, stac-geoparquet, and Overture Maps are schemas on top of that file: format_name stays GeoParquet and schema_name names the profile.

The cities file below is filtered twice: once with where on population, and once with a bounding box that also keeps only the name column. A where term has to name a column that is still loaded, so the attribute filter and the column projection are separate calls.

A binary geometry column without the geo key is still decoded as WKB, with a warning that the GeoParquet metadata is missing. A Parquet file that uses the 2025 GEOMETRY or GEOGRAPHY logical type, and has no geo key, is reported as Parquet GEOMETRY / GEOGRAPHY instead.

# Define write_geoparquet()
def write_geoparquet(path, columns, geo=None, metadata=None):
    # Set arrays
    arrays = []
    # Set fields
    fields = []
    # Loop: name, values in columns.items()
    for name, values in columns.items():
        # If isinstance(values[0], (bytes, bytearray))
        if isinstance(values[0], (bytes, bytearray)):
            # Set arrays.append(pa.array(values, type
            arrays.append(pa.array(values, type=pa.binary()))
            # Call append()
            fields.append(pa.field(name, pa.binary()))
        # Otherwise
        else:
            # Call append()
            arrays.append(pa.array(values))
            # Call append()
            fields.append(pa.field(name, arrays[-1].type))
    # Set file_meta
    file_meta = {}
    # If geo is not None
    if geo is not None:
        # Set file_meta[b"geo"]
        file_meta[b"geo"] = json.dumps(geo).encode("utf-8")
    # If metadata
    if metadata:
        # Loop: key, value in metadata.items()
        for key, value in metadata.items():
            # Set file_meta[key.encode("utf-8")]
            file_meta[key.encode("utf-8")] = value.encode("utf-8")
    # Set schema
    schema = pa.schema(fields, metadata=file_meta or None)
    # Set pq.write_table(pa.table(dict(zip(columns, arrays)), schema
    pq.write_table(pa.table(dict(zip(columns, arrays)), schema=schema), path)

COPC

Cloud Optimized Point Cloud is a LAZ file whose header carries an octree. A client range-requests the voxels inside a bounding box instead of downloading the file. This example is an uncompressed point-format 6 file with one root voxel, so it can be read without a LAZ decompressor. A compressed .copc.laz needs laspy and lazrs; the header and hierarchy are still readable without them.

Code 
# Build a minimal LAS point file and open it as cloud-native data
import struct

# Set copc_path
copc_path = CLOUD / "cloud.copc.laz"
# Set points
points = [(1.0, 2.0, 3.0), (4.0, 6.0, 8.0)]
# Set wkt
wkt = (
    # Statement
    'GEOGCS["WGS 84",DATUM["WGS_1984",SPHEROID["WGS 84",6378137,298.257223563]],'
    # Statement
    'PRIMEM["Greenwich",0],UNIT["degree",0.0174532925199433],AUTHORITY["EPSG","4326"]]'
# Call encode()
).encode("ascii") + b"\x00"
# Set scale
scale = 0.001
# Set point_blob
point_blob = bytearray()
# Loop: x_coord, y_coord, z_coord in points
for x_coord, y_coord, z_coord in points:
    # Call extend()
    point_blob.extend(
        # Call pack()
        struct.pack(
            # Include <3iHBBBBhHd
            "<3iHBBBBhHd",
            # Call int()
            int(round(x_coord / scale)),
            # Call int()
            int(round(y_coord / scale)),
            # Call int()
            int(round(z_coord / scale)),
            # Statement
            0, 0, 0, 0, 0, 0, 0, 0.0,
        # Close multi-line expression
        )
    # Close multi-line expression
    )
# Set info_payload
info_payload = struct.pack("<5dQQ2d11d", 0.0, 0.0, 0.0, 50.0, 1.0, 0, 32, 0.0, 0.0, *([0.0] * 11))
# Set vlr_copc

# Set vlr_copc[2:6]
vlr_copc[2:6] = b"copc"
# Call pack_into()
struct.pack_into("<HH", vlr_copc, 18, 1, len(info_payload))
# Set vlr_copc[54:]
vlr_copc[54:] = info_payload
# Set vlr_wkt

# Set vlr_wkt[2:18]

# Call pack_into()

# Set vlr_wkt[54:]

# Set hier_offset

# Call pack_into()
struct.pack_into("<Q", vlr_copc, 54 + 40, hier_offset)
# Call pack_into()
struct.pack_into("<Q", vlr_copc, 54 + 48, 32)
# Set xs, ys, zs

# Set header[24]

# Set header[25]
header[25] = 4

# Call pack_into()

# Call pack_into()
struct.pack_into("<I", header, 100, 2)
# Set header[104]

# Call pack_into()

# Call pack_into()

# Call pack_into()

# Set hierarchy

# Call write_bytes()

def spatial_ref(crs):
    # Include Build an OSR spatial reference from a geolattice CRS, EPSG code, or CRS string.
    """Build an OSR spatial reference from a geolattice CRS, EPSG code, or CRS string."""
    # Set srs
    srs = osr.SpatialReference()
    # If hasattr(crs, "to_wkt")
    if hasattr(crs, "to_wkt"):
        # Call ImportFromWkt()
        srs.ImportFromWkt(crs.to_wkt())
    # Else if isinstance(crs, int)
    elif isinstance(crs, int):
        # Call ImportFromEPSG()
        srs.ImportFromEPSG(int(crs))
    # Otherwise
    else:
        # Call SetFromUserInput()
        srs.SetFromUserInput(str(crs))
    # Call SetAxisMappingStrategy()
    srs.SetAxisMappingStrategy(osr.OAMS_TRADITIONAL_GIS_ORDER)
    # Return result
    return srs

Visualize written files

These maps read files from Data/00_shared/vector_data/output_folder. They do not reuse the features still held in memory from the write step.

The first figure compares four county outputs: the shapefile and FlatGeobuf stay in the Albers projection, the KML is in EPSG:4326, and the GPX file is the county waypoints. The next map draws those waypoints on the county shapefile. plot_layers reprojects the waypoints onto the shapefile CRS. The choropleth uses SQUARE_MIL from the written shapefile. The last figure reads six shapefiles that were converted from the GDAL samples: polygons, points, and lines.
