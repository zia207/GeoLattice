Vector Data

Library: geolattice.vector

Overview

Vector data is one of the two fundamental spatial data models in Geographic Information Science (GIS). It represents the world as a collection of discrete objects, points, lines, and polygons, each carrying both a geometric shape (where it is) and an attribute table (what it is). Unlike raster data, which divides the world into a grid of uniform cells, vector data captures features with crisp boundaries and precise coordinates, making it the natural choice for roads, administrative boundaries, building footprints, water networks, survey points, and countless other real-world entities.

This notebook serves as the entry point for Module 01 of GeoLattice. It explains what vector data is, why it matters, and provides a structured overview of every sub-notebook available in this module.

1. What is Vector Data?

Vector data represents geographic features as mathematically defined geometric objects embedded in a coordinate space. Each feature is an individual entity with:

  • A geometry: one or more coordinate pairs (x, y, and optionally z and m) that define its shape and location.
  • An attribute record: a row in a table of properties (name, population, land use class, date, etc.) associated with that geometry.

Geometry Types

The Open Geospatial Consortium (OGC) Simple Features standard, implemented by virtually every GIS library, defines the following geometry types:

Geometry Type Description Real-world examples
Point A single coordinate pair (x, y) Weather station, well, tree, city centroid
MultiPoint A collection of points treated as one feature ATM locations for a single bank branch
LineString An ordered sequence of coordinate pairs forming an open path Road segment, river reach, utility line
MultiLineString A collection of linestrings as one feature Complete highway route with multiple segments
Polygon A closed ring of coordinates enclosing an area, with optional interior holes Country boundary, lake, land-use parcel
MultiPolygon A collection of polygons as one feature Country with islands, archipelago
GeometryCollection A heterogeneous mix of any geometry types Complex infrastructure asset

Attributes and the Feature Table

Beyond geometry, each feature carries attributes, tabular data stored alongside the geometry in a format like a database table. Attributes can be integers, floats, strings, dates, or booleans, and they are what make vector data analytically powerful. You can join external tables, compute new fields, filter features by attribute value, and group features to produce summary statistics, all within a GIS environment.

Comparison with Raster Data

Aspect Vector Raster
Representation Discrete objects (points, lines, polygons) Continuous grid of cells (pixels)
Storage Coordinate lists + attribute table Array of values
Precision Exact boundary coordinates Resolution-limited
Best for Features with well-defined boundaries Continuous phenomena (elevation, temperature)
File size Scales with feature count Scales with spatial extent × resolution
Editing Easy to add, move, delete individual features Must modify cell values
Analysis Overlay, network, proximity, geoprocessing Map algebra, surface analysis, image processing

2. Why Vector Data Matters

Vector data underpins a vast range of real-world workflows across every discipline that relies on location:

  • Urban Planning & Land Use: Cadastral parcels, zoning polygons, road centrelines, and building footprints are all vector datasets that planners use for site analysis, infrastructure design, and zoning enforcement.
  • Environmental Science: Habitat boundaries, watershed delineations, protected-area polygons, and species-occurrence point records are collected and analysed as vector data.
  • Public Health: Disease case locations (points), catchment areas of clinics (polygons), and travel routes to facilities (lines) are core to health geography and epidemiology.
  • Transportation & Logistics: Road, rail, and shipping networks are stored as routable vector line graphs with attributes (speed limit, capacity, travel time).
  • Agriculture: Field boundaries and irrigation canal networks are vector datasets used in precision agriculture and farm management systems.
  • Disaster Management: Flood inundation extents, evacuation route lines, and affected-community polygons are produced during emergency response as vector layers.
  • Business Intelligence: Customer locations, store catchment areas, and territory boundaries are spatial layers that drive retail location analysis and market segmentation.

Python, through GeoPandas, Shapely, Fiona, PyProj, and Matplotlib / Folium / Plotly, has become the dominant open-source stack for vector data work. GeoLattice wraps these libraries behind a consistent, learner-friendly API organised around the workflows covered in this module.

3. Core Concepts

Before diving into the notebooks, the following concepts are worth reviewing.

3.1 Coordinate Reference Systems (CRS)

All vector data has coordinates. Those coordinates are meaningless without a Coordinate Reference System that defines the datum, ellipsoid, and projection used to convert the curved surface of the Earth into a flat (or 3-D) coordinate space.

CRS Type Description When to use
Geographic (lon/lat) Angles in degrees on a reference ellipsoid (e.g., WGS 84 / EPSG:4326) Data storage, global mapping, GPS exchange
Projected Metres or feet on a flat surface (e.g., UTM, BTM, US National Atlas) Distance, area, and buffer calculations
Local / engineering Arbitrary origin, often in feet (e.g., State Plane) Engineering surveys, cadastral work

Key rule: Always reproject to a suitable projected CRS before computing distances, areas, or buffers. Using longitude/latitude for these operations gives wrong results because degrees are not a constant unit of distance.

3.2 Common Vector File Formats

Format Extension Notes
Shapefile .shp + sidecar files Legacy Esri standard; ubiquitous but limited (255-char field names, 2 GB cap, no NULL)
GeoJSON .geojson Human-readable, web-native; always uses WGS 84 by spec; not ideal for large datasets
GeoPackage .gpkg Modern, single-file SQLite container; supports multiple layers, raster tiles, extensions
FlatGeobuf .fgb Cloud-optimised, streamable; ideal for large datasets served over HTTP
GeoParquet .parquet Columnar analytics format; best for large-scale joins and aggregations
KML / KMZ .kml, .kmz Google Earth format; stores style information alongside geometry
File GDB .gdb Esri proprietary geodatabase; readable via GDAL with limitations
CSV + WKT/XY .csv Tabular data with coordinates; geometry must be parsed from a column

3.3 The GDAL/OGR Stack

Almost every Python vector library reads and writes data via GDAL/OGR under the hood:

Your code (GeoPandas / Fiona / GeoLattice)
        ↓
    GDAL / OGR
        ↓
  File / database / remote source
  (Shapefile, GeoPackage, PostGIS, S3 GeoParquet, ...)

GeoLattice exposes a higher-level API on top of this stack while keeping the full power of GDAL drivers available.

3.4 The GeoDataFrame

In the Python ecosystem, the central data structure for vector data is the GeoDataFrame (GeoPandas). It extends a Pandas DataFrame with:

  • A geometry column (Shapely geometry objects).
  • A .crs attribute storing the Coordinate Reference System.
  • Spatial methods: .to_crs(), .buffer(), .sjoin(), .dissolve(), .plot(), and more.

All GeoLattice vector functions accept and return GeoDataFrames, making them fully interoperable with the broader GeoPandas/Pandas ecosystem.

Key Design Principles

Principle What it means in practice
GeoDataFrame-first All functions accept and return geopandas.GeoDataFrame or GeoSeries
GDAL/OGR backed I/O functions support every format GDAL can read or write
CRS-aware Projection mismatches raise clear errors; reprojection is explicit
Shapely 2.x compatible All geometry operations use Shapely 2.x vectorised routines
Matplotlib + Folium Static maps use Matplotlib; interactive maps use Folium
Learner-friendly Functions have sensible defaults; verbose error messages explain what went wrong

Work through every notebook in order. Each notebook introduces one layer of the stack and prepares you for the next.

Path B: Task-Oriented (For practitioners with some GIS experience)

Jump directly to the notebook that matches your immediate need:

Fix a CRS mismatch or reproject a layer 01.02

Summary

Module 01 of GeoLattice provides a complete, practitioner-oriented introduction to vector data structured around five core workflows:

# Sub-notebook Core Library What you can do after
01.01 Read / Write GDAL/OGR, Fiona Load any vector format; export to Shapefile, GeoJSON, GeoPackage, and more
01.02 CRS & Projections PyProj, GeoPandas Inspect, assign, and reproject vector layers confidently
01.03 Visualisation Matplotlib, Folium Make publication-quality static maps and interactive web maps
01.04 Geoprocessing GeoPandas, Shapely Clip, buffer, dissolve, intersect, and join vector layers
01.05 Geometry Operations Shapely 2.x Create, transform, clean, and measure individual geometries

All sub-modules share a consistent design philosophy: GeoDataFrame-first, CRS-aware, and GDAL-backed. Together they build the spatial data skills needed as a foundation for Module 02 (Raster Data) and Module 03 (Spatial Analysis).

Happy mapping! 🗺️
